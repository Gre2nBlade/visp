# Control Plane и серверный агент

## Коротко

Control Plane — это API и управляющий сервис Visp для владельца инфраструктуры. Он не заменяет API вашего сайта или Telegram-бота. Он предоставляет готовые операции: создать код, задать лимиты, активировать устройство, отозвать доступ, получить состояние сервера и отправить команду агенту.

Серверный агент — небольшой компонент на VPS владельца. Он устанавливает и обновляет протоколы, запускает локальные компоненты и отправляет health-события. Агент сам открывает исходящее mTLS-соединение с Control Plane; владельцу не нужно открывать SSH или отдельный входящий порт для каждой операции.

## Зачем нужны оба компонента

```text
Сайт / Telegram-бот / CRM
          │ HTTPS + OIDC service account
          ▼
Control Plane API (коды, лимиты, RBAC, аудит)
          │ исходящее mTLS-соединение
          ▼
Visp Agent на сервере владельца
          │ localhost / Docker network
          ▼
VPN, proxy, DNS или другой компонент
```

Control Plane хранит правила и состояние. Агент выполняет локальные операции. Studio — пользовательский интерфейс для владельца, который вызывает тот же API. Обычный пользователь Visp не видит Control Plane и агента.

## Пример: кнопка на сайте

Кнопка «Выдать доступ» вызывает backend сайта, а не Control Plane напрямую из браузера:

```http
POST /v1/code-sets
Authorization: Bearer <service-token>
Idempotency-Key: order-1842
Content-Type: application/json

{
  "server_ids": ["srv_01"],
  "profiles": ["zapret-main"],
  "limits": {"devices": 2, "days": 30},
  "label": "order-1842"
}
```

Backend сайта получает ответ с кодом один раз, сохраняет только безопасный идентификатор и показывает пользователю QR или ссылку Visp. Секретный service token никогда не помещается в HTML, JavaScript или Telegram-клиент.

## Пример: Telegram-бот

1. Владелец создаёт для бота отдельный OIDC service account с областью `codes:create` и лимитом запросов.
2. Пользователь нажимает `/get_access`.
3. Бот проверяет оплату/роль в своей базе.
4. Backend бота вызывает `POST /v1/code-sets` с `Idempotency-Key = telegram:<chat_id>:<period>`.
5. Бот отправляет пользователю короткую ссылку или QR.
6. При `/revoke` backend вызывает `POST /v1/codes/{id}/revoke`.

Webhook Control Plane может уведомить backend бота о `code.activated`, `code.expired`, `agent.unhealthy`; подпись webhook проверяется до обработки.

## Самостоятельное размещение

Владелец может развернуть Control Plane в Docker Compose на своём VPS. Для первой установки Studio создаёт одноразовый bootstrap-токен. Команда установки регистрирует агент, после чего токен становится недействительным. Миграции PostgreSQL, резервные копии, OIDC и ключи подписи остаются ответственностью владельца self-hosted Control Plane.

## Когда Control Plane не нужен

Для личного офлайн-кода `visp://`, ручной конфигурации или локального прокси можно работать без Control Plane. Он нужен, когда требуется выдавать много кодов, ограничивать устройства/трафик, отзывать доступ, подключать сайт или бота и управлять несколькими серверами.
