# Экраны Visp

Полное описание всех экранов приложения: назначение, структура, состояния,
действия и навигация. Документ описывает **фактическую реализацию**, включая
нереализованные места, — чтобы расхождение между интерфейсом и планами не было
сюрпризом.

Связанные документы: [DESIGN.md](DESIGN.md) — визуальный язык,
[docs/ENGINES.md](docs/ENGINES.md) — движки.

Всего 15 экранов: 5 корневых вкладок (3 из них условные) и 10 экранов,
открываемых поверх.

---

## Карта навигации

### Корневой каркас

`RootShell` (`lib/features/navigation/root_shell.dart`) — единственный экран
с `bottomNavigationBar`. Он не имеет собственного `AppBar`, заголовка и FAB.

Состав вкладок собирается динамически:

```
Главная → Серверы → [Прокси] → [Studio] → Настройки
                        ↑           ↑
              только если установлен   только если Studio
              плагин «Прокси»          закреплён в навигации
```

| Вкладка | Экран | Условие появления |
|---------|-------|-------------------|
| Главная | `HomeScreen` | всегда |
| Серверы | `ServersScreen` | всегда |
| Прокси | `ProxyScreen` | `AppState.proxyInstalled` |
| Studio | `StudioScreen` | `AppState.studioPinned` |
| Настройки | `SettingsScreen` | всегда |

Порядок и набор пересчитываются на каждом `notifyListeners()`, поэтому
установка плагина или открепление Studio мгновенно меняет панель. Если текущая
вкладка исчезла, индекс сбрасывается на 0.

### Плавающая панель

`VispFloatingNav` (`lib/features/navigation/visp_floating_nav.dart`):

| Параметр | Значение |
|----------|----------|
| Высота панели | 68 px |
| Внешние отступы | 16 по горизонтали, 4 сверху, 8 снизу |
| Радиус капсулы | 16 (`AppRadius.s`) |
| Внутренний отступ капсулы | 6 px |
| Зазор до кнопки «+» | 10 px |
| Кнопка «+» | 56 px, радиус 28 |
| Размер иконки вкладки | 22 px, залитая у активной |
| Подпись вкладки | 11 px, одна строка, сжимается целиком |
| Активная вкладка | заливка `muted`, рамка `primary` 40 %, иконка `primary` |
| Анимация | 200 мс `easeOut` (иконка), 220 мс `easeOutCubic` (скольжение) |

Панель `extendBody: true` — контент экранов уходит под неё. **Поэтому каждый
прокручиваемый экран обязан иметь нижний отступ `AppSpacing.xxl + 56` = 88 px**,
иначе последний элемент перекроется панелью.

Нажатие активной вкладки игнорируется (`if (i == currentIndex) return`), без
тактильной отдачи и без пересборки.

### Ключевой технический факт

Тела вкладок подставляются напрямую: `_screenFor(current)`. `IndexedStack` и
`AutomaticKeepAliveClientMixin` **не используются**, поэтому при смене вкладки
дерево элементов уничтожается и строится заново. Позиции скролла, текст полей и
локальный `State` экранов теряются.

Исключение — состояние списка серверов (поиск, фильтры, раскрытие групп) и
`studioPinned`: оно живёт в `AppState`, поэтому переживает переключение вкладок.

### Арсенал экранов

Все маршруты — `MaterialPageRoute`, именованных маршрутов нет.

## Общие правила

### Отступы и заполнение

| Контекст | Отступ |
|----------|--------|
| Горизонтальные поля экрана | `AppSpacing.l` = 16 |
| Скролл с панелью снизу | `AppSpacing.xxl + 56` = 88 |
| Горизонтальные поля главной | `AppSpacing.l` = 16 |
| Пустое состояние | `AppSpacing.xxl` = 32 |

### Три способа сообщить пользователю

1. **Тост** (`VispToast`) — для результата действия: «Добавлено подключений: 3».
2. **Инлайн-текст в цвет `destructive`** — для ошибки соединения на главном экране.
3. **Диалог подтверждения** — только для необратимых действий (удаление сервера,
   сброс настроек).

Принцип: неподдерживаемое действие **объясняется текстом, а не выглядит
работающим**. Это осознанный продуктовый выбор — заглушка честнее «успешного»
сообщения о том, чего не произошло.

### Модальные шторки

Используются для выбора из списка и подтверждения разрешений. Общая форма:

```
backgroundColor: Colors.transparent
Container(
  color: colors.card,
  borderRadius: BorderRadius.vertical(top: Radius.circular(24)),
  padding: EdgeInsets.all(AppSpacing.l),
  child: SafeArea(top: false, child: Column(mainAxisSize: min, ...)),
)
```

Высота подстраивается под контент; для длинных списков используется
`isScrollControlled: true` и `Flexible` внутри.

### Чего нет на экранах

- Скелетонов и спиннеров почти нигде: вместо них тосты и встроенное состояние
  кнопки `loading`.
- Пустые состояния есть только там, где список может быть пуст (главная без
  подключений, поиск без результатов, Studio без своих серверов, прокси).
- `FutureBuilder` в приложении нет.

## 1. Главная

**Файл** `lib/features/connection/screens/home_screen.dart` (762 строки)
**Класс** `HomeScreen extends StatelessWidget`

Единственный экран с блюпом. Содержит действие подключения в центре фигуры и
запасной панели ввода кода, когда подключений ещё нет.

### Ветка без подключений

Определяется условием `AppState.hasConnections`. Вместо пустого экрана
показывается рабочая панель:

```
BlupVisp(size: 120, status: idle, motionReduced: …)
«Подключений ещё нет»                              display
«Вставьте код или ссылку, чтобы добавить подключение»
VispInput «Вставьте ключ/ссылку/код»   [Вставить]
[Self-hosted] [Файл с настройками] [QR-код]
```

- `hintText` поля: `visp://, VISP-код, vless://, hysteria2://, ss://, trojan://,
  vmess://, подписка, tg://proxy`.
- Отправка по клавиатуре (`go`) и по кнопке «Вставить» ведут в
  `AddConnectionScreen.openWithPreview`; при успехе поле очищается, показывается
  тост «Добавлено подключений».
- Три быстрые кнопки открывают нужный раздел экрана добавления сразу:
  `AddSection.selfHosted`, `.file`, `.qr`.
- `motionReduced` здесь учитывается — фигура замирает.

### Ветка с подключениями

```
_StatusText            заголовок состояния + подпись «Протокол | адрес»
Spacer
BlupLayer              блюп, в центре — действие подключения
[ошибка]               текст colors.destructive под фигурой
[чип]                  «Трафик заблокирован», ChipTone.danger
_ProtocolSelector      кнопка выбора протокола
[_DebugBlock]          только при state.debugVisible
_ServerCard            текущий сервер + раздельное туннелирование
```

#### Статус и подпись

| `BlupStatus` | Заголовок | Цвет |
|--------------|-----------|------|
| `idle` | «VPN выключен» | `foreground` |
| `preparing` / `checking` / `connecting` / `reconnecting` | `statusDetail` ?? «Подключиться» | `foreground` |
| `connected` | «Подключено» | `primary` |
| `error` | первое предложение `errorText` | `destructive` |
| `blocked` | «Трафик заблокирован» | `destructive` |

Подпись строкой ниже: `AmneziaWG | 2.27.63.201` либо «Не выбрано».

#### Действие в центре блюпа

`BlupLayer` вычисляет размер фигуры от доступной площади:
`min(width - 104, height - 8)`, ограничение 96…236 px.

| Состояние | Поведение нажатия |
|-----------|-------------------|
| `connected` | отключение |
| нет выбранного профиля | тост «Не выбрано» с действием «Добавить подключение» |
| иначе | подключение |
| идёт установка | отмена подключения |

Во время установки прогресс показывает янтарная дуга по кольцу фигуры, поэтому
кнопка в центре не дублирует его спиннером.

#### Выбор протокола

Кнопка открывает шторку «Выбор протокола» с подзаголовком
`{имя} · {адрес}`. Для каждого профиля: название, описание протокола,
`адрес:порт`, чип состояния движка и галочка у выбранного.

Если соединение активно и выбран другой профиль — `AlertDialog`:
«Смена протокола при активной сессии переподключит соединение», действия
«Отмена» / «Продолжить».

#### Карточка сервера

Строка из стекла (или плоская поверхность при выключенном стекле) открывает
шторку «Список серверов» — это `ServersContent` без поиска и фильтров.

Под ней карточка с одной строкой «Раздельное туннелирование» и переключателем,
который ведёт в `SplitTunnelingScreen`.

#### Debug-блок

Показывается только при `state.debugVisible`. Шесть показателей в три колонки:
загрузка и отдача в Mb/s, пинг в ms, протокол, время сессии `ЧЧ:ММ:СС`.
Отсутствующее значение — «Нет данных», а не ноль. Обёрнут в `VispGlassPanel`:
преломление внутри прокручиваемого списка даёт артефакты по краям.

#### Доступные действия

| Действие | Результат |
|----------|-----------|
| Поле кода → Enter / «Вставить» | предпросмотр импорта |
| «Self-hosted» / «Файл с настройками» / «QR-код» | нужный раздел экрана добавления |
| Нажатие на блюп | подключение / отключение / отмена |
| Нажатие на кнопку протокола | шторка выбора протокола |
| Выбор протокола | смена профиля, при активной сессии — с подтверждением |
| Нажатие на карточку сервера | шторка со списком серверов |
| Переключатель туннелирования | `setSplitTunneling` |
| Строка «Раздельное туннелирование» | переход на `SplitTunnelingScreen` |

### Состояния

- **Ошибка соединения** — инлайн-текст под блюпом плюс заголовок в
  `destructive`. Отдельного тоста нет: ошибка принадлежит экрану, а не действию.
- **Трафик заблокирован** — чип `ChipTone.danger`.
- **Нет данных** в debug — текст «Нет данных».
- **Отсутствие контрола** вместо дизейбла: селектор протокола возвращает
  `SizedBox.shrink()`, если нет профиля; debug-блок не рендерится.

### Замечания

- `motionReduced` передаётся только в пустую ветку: `BlupLayer` его не
  использует, поэтому фигура при активном соединении анимируется всегда.
- Комментарий про «кнопку в центре блюпа» прикреплён к `_DebugBlock`, а сама
  кнопка живёт в `BlupLayer` / `BlupAction`.
- `Stack` с единственным `Positioned.fill` избыточен.

## 2. Добавить подключение

**Файл** `lib/features/connection/screens/add_connection_screen.dart` (325 строк)
**Класс** `AddConnectionScreen extends StatefulWidget`

Единая точка входа: поле кода плюс четыре альтернативных способа.

```
AppBar «Добавить подключение»
VispInput «Вставьте ключ/ссылку/код»          [Вставить]
[Продолжить]                                  expanded, primary
ДРУГИЕ ВАРИАНТЫ ПОДКЛЮЧЕНИЯ
┌─ карточка ────────────────────────────┐
│ Self-hosted · Настроить VPN на своём… │ server
│ Файл с настройками · OpenVPN, WG…      │ file
│ QR-код · Сканировать код камерой      │ qr
│ Импорт подписки · base64, sing-box…   │ refresh
└────────────────────────────────────────┘
```

### Разделы

`enum AddSection { key, selfHosted, file, qr, subscription }`. Экран открывается
через два фабричных метода:

- `AddConnectionScreen.open(context, initialSection: …)` — можно сразу открыть
  нужный раздел; `selfHosted`, `file`, `qr` вызываются в
  `addPostFrameCallback`, чтобы первый кадр не пропадал.
- `AddConnectionScreen.openWithPreview(context, code)` — общий воронка разбора.

### Разбор кода (`openWithPreview`)

1. `CodeImporter.parse(code)`.
2. `ImportKind.unknown` → тост-ошибка с причиной или «Формат пока не
   поддерживается». Поле и экран не меняются.
3. `ImportKind.devActivation` → `activateDevCode`; успех — «Код активирован»,
   неудача — «Неверный код». Экран закрывается (`false`), поле не очищается.
4. Иначе → `Navigator.push<bool>` на `ImportPreviewScreen`. Возврат `true`
   означает «добавлено», и вызывающий очищает своё поле.

### Импорт подписки

Шторка «Импорт подписки» с пояснением «base64, Clash YAML, sing-box JSON,
Xray JSON. Адрес подписки с токеном считается секретом» и полем URL. Отправка
кладёт адрес в основное поле и сразу запускает разбор.

### Состояния

- Ошибка — тост для «Нет данных» (пустой буфер), для неподдерживаемого формата и
  для неверного кода.
- `VispInput.errorText` подключён к `_codeError`, но само поле **никогда не
  заполняется**: инлайн-ошибка не показывается никогда.
- Загрузки и дизейбла нет: «Продолжить» и «Вставить» активны всегда.

### Замечания

- `VispToast.showError(..., actionLabel: s.paste)` вызывается без `onAction`, а
  тост делает `actionLabel != null ? (actionLabel, onAction!) : null` — на пути
  неподдерживаемого формата это упадёт. Корректный образец есть в `blup_layer.dart`.
- Контроллер поля в шторке подписки не освобождается.
- `_divider` и `_SectionTitle` дублируют помощники других экранов.

## 3. Сканирование QR

**Файл** `lib/features/connection/screens/qr_scan_screen.dart` (161 строка)
**Класс** `QrScanScreen extends StatefulWidget`

Полноэкранный сканер на `mobile_scanner`. Камера включается только на время
сканирования и останавливается сразу после находки.

```
AppBar «QR-код», прозрачный, белый текст
MobileScanner                 рамка наведения 240×240, радиус 30, primary 2 px
                              чип «Наведите на код или ссылку протокола»
                              [Отмена] secondary, expanded
```

### Поведение

- Первое распознанное значение с непустым `rawValue` → `_controller.stop()` →
  `Navigator.pop(value.trim())`. Флаг `_handled` защищает от повторной обработки.
- «Отмена» и системная назад-кнопка возвращают `null`.
- `openQrScanFlow(context)` передаёт результат в
  `AddConnectionScreen.openWithPreview`, замыкая цепочку
  «Добавление → QR → Предпросмотр».

### Состояние ошибки

`errorBuilder` заменяет область сканера на `_ScannerError`: иконка 32,
«Камера недоступна. Разрешите доступ в настройках или вставьте код вручную.» и
кнопка «Повторить» (`_controller.start()`). Чип и «Отмена» остаются
поверх — отказ остаётся доступным при ошибке камеры. Причина исключения
игнорируется и пользователю не показывается.

### Замечания

Три строки захардкожены по-русски вместо `S`: чип, текст ошибки и «Повторить»
(хотя `s.retry` существует). Таймаута и подсказки «приблизьте» нет.

## 4. Предпросмотр импорта

**Файл** `lib/features/connection/screens/import_preview_screen.dart` (382 строки)
**Класс** `ImportPreviewScreen extends StatefulWidget`

Показывает, что приложение поняло из кода, и позволяет отказаться от части
профилей. Единственный экран, где явно виден запрет на молчаливую подмену
локальных правил.

```
AppBar «Предпросмотр импорта»
┌─ карточка ──────────────────────────────────┐
│ <название источника>                h1      │
│ Источник: <тип>                              │
│ [VPN: 3] [Прокси: 1] [Правила маршрутизации] │
│ [Нужны модули]                               │
└──────────────────────────────────────────────┘
«Все профили будут добавлены»   ← подпись переключателей
┌─ карточка ──────────────────────────────────┐
│ ▸ профиль   [Нужен модуль]            (вкл) │
│ ▸ профиль   [Плагин «Прокси»]         (вкл) │
└──────────────────────────────────────────────┘
┌─ карточка правил маршрутизации (если есть) ─┐
│ Оставить мои / Объединить / Заменить         │
└──────────────────────────────────────────────┘
[Добавить]                                     expanded, loading
```

### Состояния

- Все записи выбраны по умолчанию; подпись под списком меняется на
  «Отмечено 2 из 3. Снимите отметку, чтобы не добавлять профиль».
- Пока ничего не выбрано и нажата «Добавить» — тост «Не выбрано».
- Применение показывает `loading` у кнопки и дизейблит её. Технически флаг
  живёт внутри одного синхронного кадра и служит защитой от повторного входа.
- Прокси-записи при отсутствии плагина не добавляются, а пользователь видит
  тост «Прокси для Telegram: установите плагин, чтобы добавить запись».

### Правила маршрутизации

Три варианта: «Оставить мои» (по умолчанию), «Объединить», «Заменить».
Пояснение в карточке: «Правила из кода не заменяют локальные настройки молча.
Выберите способ применения.»

### Замечания

- **Выбор способа не применяется.** `_rulesChoice` не передаётся в
  `applyImport`, а тот правила маршрутизации игнорирует. Сейчас это честно
  выглядящий, но нерабочий элемент управления.
- Пустого состояния нет: при нуле записей карточка просто пустая, видна только
  подпись «Отмечено 0 из 0».
- `rawCode` сохраняется, но не читается — показать исходный код нельзя.
- Пять строк захардкожены, минуя `S`.

### Что работает

Только главный переключатель: он пишется в `Preferences` и переживает перезапуск,
а его описание дублируется на главном экране.

### Что не работает

- Список доменов засеян двумя значениями (`example.com`, `10.0.0.0/8`) и
  показывается как будто это данные пользователя. Он живёт только в `State`
  виджета и теряется при выходе.
- Направление «Через VPN / Напрямую» — тоже локальное состояние без сохранения.
- «Импорт файла» и «Ссылка на список» показывают тост, но ничего не открывают.
- Режим приложений не применяет ничего: первая строка имеет пустой обработчик,
  вторая — тост «Неподдерживаемая функция поясняется, а не выглядит
  работающей».
- Валидации ввода нет: принимается любая непустая строка.
- Пустое состояние списка («Список пуст: добавьте домен или импортируйте
  файл») недостижимо, пока список засеян.

Почти все строки захардкожены; из `S` приходят только заголовок и «Добавить».
Терминологическое правило экрана: «Напрямую» и «через другое VPN-подключение» —
разные режимы и намеренно не объединены.

### Вкладка «Протоколы»

По карточке на профиль: название, описание протокола, `Порт N`, чип источника и
чип состояния (`Выбран` / состояние движка / «Готов к подключению»). Кнопка

- «Автоустановка» — **только для своих серверов**, у остальных карточка скрыта.

  Пояснение: «Удаление локальной записи не удаляет сервер у владельца. Если
  запись используется, соответствующая сессия будет завершена.»

### Состояния

- Если `hostId` больше не существует — минимальный экран с текстом «Нет данных».
- Пустые профили — только пояснение внизу, без явного сообщения.
- Загрузки нет: `selectProfile` и `deleteHost` ожидаются без индикатора.
- Кнопка подтверждения в диалоге подписана «Продолжить», а не «Удалить», и не

### Замечания

Вкладки собраны вручную (`GestureDetector` + нижняя линия), без

### Установка прокси

локальная сеть, уведомления, фоновая работа, зависимость от движка прокси.

чип «Работает», а вкладка «Прокси» появляется в навигации.

Оба экспериментальных модуля при установке честно отказывают тостами:
«Модуль не подготовлен для этой платформы» и «Экспериментальный модуль:
совместимость проверяется».

## Сводка: что заявлено, но не работает

Собрано, чтобы состояние проекта не выглядело лучше, чем он есть.

| Место | Что не работает |
|-------|-----------------|
| Предпросмотр импорта | выбор «Оставить мои / Объединить / Заменить» не применяется |
| Раздельное туннелирование | список доменов и направление не сохраняются; импорт и ссылка — тосты; режимы приложений не применяются |
| Добавить подключение | `VispInput.errorText` не заполняется; тост с `actionLabel` без `onAction` упадёт |
| Прокси | кнопки интервала — пустые обработчители; нет состояний «Запускается» и «Ошибка» |
| Studio | чипы обзора владельца — константы, поданные как реальные данные |
| Карточка сервера | переименование, настройки сервера, автоустановка, скачивание движка — заглушки |
| Персонализация | каталог тем и иконок — заглушки; образцы не нажимаются |
| Always-on, логирование, DNS-проверка | тосты с пояснением |
| Self-hosted | ошибки полей не заполняются; установка без отмены и этапов |
| Главная | `motionReduced` не доходит до активного блюпа |
| Импорт подписки по URL | сети нет: URL без содержимого честно отклоняется |
| VISP-код | распознаётся, серверная проверка не подключена |
| olcRTC | профиль сохраняется, ядро отсутствует |

Общий принцип, которому следует большинство заглушек: действие, которое не
работает, объясняет это текстом и не имитирует успех. Исключения — кнопки
интервала в «Прокси», которые не делают вообще ничего.
